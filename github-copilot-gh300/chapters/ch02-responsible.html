Chương 02 Using Copilot Responsibly

Dùng Copilot có trách nhiệm

Cốt lõi: Copilot là trợ lý, không phải nguồn chân lý. Mọi đầu ra phải được kiểm chứng — đây cũng là phần chiếm 15-20% điểm thi.

Bức tranh lớn

AI sinh (generative AI) có rủi ro cố hữu; dùng có trách nhiệm nghĩa là hiểu rủi ro, có biện pháp giảm thiểu, và luôn xác thực đầu ra trước khi dựa vào nó.

Tự kiểm tra5 điều bắt buộc nhớ

  1. Vì sao phải xác thực đầu ra của AI?

    Vì LLM có thể "ảo giác" (hallucinate), tạo code sai hoặc lỗ hổng bảo mật; bạn chịu trách nhiệm với code mình dùng.

  2. Ba nhóm rủi ro chính của generative AI?

    Thông tin sai (hallucination), code không an toàn, và thiên kiến/ vấn đề bản quyền.

  3. Biện pháp giảm thiểu phổ biến?

    Review bằng người, viết test, quét bảo mật, content exclusions, lọc code trùng public.

  4. "Vận hành Copilot có trách nhiệm" là gì?

    Luôn xem xét, kiểm thử và xác nhận đúng đắn trước khi tin dùng kết quả.

  5. Nên đối xử với code do AI tạo như thế nào?

    Như code của đồng nghiệp: đánh giá, kiểm thử, xác nhận — không merge vô điều kiện.

Ghi chúNguyên tắc AI có trách nhiệm

Dùng AI có trách nhiệm đòi hỏi nhận thức rõ rủi ro và giới hạn của generative AI:

  • Hallucination — mô hình tạo ra nội dung nghe hợp lý nhưng sai thực tế (API không tồn tại, cú pháp sai).
  • Code không an toàn — gợi ý có thể chứa lỗ hổng (injection, thiếu validate input…).
  • Thiên kiến (bias) — đầu ra phản ánh thiên kiến trong dữ liệu huấn luyện.
  • Bản quyền & licensing — code có thể trùng code công khai; cần chú ý nguồn gốc.

Trách nhiệm cuối cùng nằm ở người dùng: bạn duyệt và chịu trách nhiệm với từng dòng code được áp dụng.

Ghi chúTác hại tiềm ẩn và biện pháp giảm thiểu

Tác hại tiềm ẩnBiện pháp giảm thiểu
Code sai logic / hallucinationReview từng dòng, chạy thử, viết unit test
Lỗ hổng bảo mậtQuét code, dùng tools bảo mật, code review
Thiên kiến trong đầu raNhận thức và đa dạng hóa input, xem xét ngữ cảnh
Lộ dữ liệu / bí mậtContent exclusions, không dán secret vào prompt
Trùng code publicBật lọc "suggestions matching public code"

Ghi chúXác thực và vận hành có trách nhiệm

Quy tắc vàng: assess → test → confirm. Đánh giá output như khi review code của đồng nghiệp; chạy test và kiểm chứng tính đúng đắn trước khi tin dùng.

Không bao giờ dán bí mật (token, khóa API, mật khẩu) vào prompt — Copilot dùng prompt làm ngữ cảnh; và chỉ nên cho Copilot truy cập đúng phần repo cần thiết.

Vận hành có trách nhiệm còn gồm: hiểu chính sách của tổ chức, dùng content exclusions cho file nhạy cảm, và ghi nhớ rằng Copilot không thay thế phán đoán con người.

Thực hànhÁp lên máy

  • 1. Soi một gợi ýNhờ Copilot viết hàm xử lý input người dùng, rồi tự tìm lỗ hổng trước khi dùng.
  • 2. Test trước khi tinVới code Copilot sinh, viết unit test và chạy để xác nhận hành vi.
  • 3. Nhận diện hallucinationHỏi Copilot một API "tưởng tượng", kiểm tra xem nó có tự tin bịa không.
  • 4. Bảo vệ secretKiểm tra prompt của bạn không chứa token/khóa trước khi gửi.

Ngoài sáchMẹo thi bổ sung
