Chapter 06 Prompt Engineering & Context Crafting

Prompt engineering and context

Answer quality depends heavily on how you write prompts and supply context. This is a skill the exam measures directly.

The big picture

A good prompt = a clear goal + enough examples + the right context + iteration. Copilot uses both the prompt and surrounding context to answer.

Recall check5 things you must remember

  1. Best prompt order?

    Start general, then get specific; put the most important requirements first and last.

  2. Why give examples?

    Input/output examples help Copilot understand the expected format and behavior.

  3. Zero-shot vs few-shot?

    Zero-shot has no examples; few-shot includes a few examples to guide the model.

  4. How to provide context?

    Open relevant files, highlight code, use @ (files/symbols) and # (issues/PRs), instructions files.

  5. What if the result is not good?

    Iterate: adjust the prompt, retry, keep history relevant.

NotesPrompt structure

A prompt has a request plus context. State the broad goal first, then list specific requirements, placing the most important ones at the beginning and end since Copilot weights them more.

State rules directly rather than as meta-instructions: write "Return JSON" instead of "remember to always return JSON".

NotesZero-shot and few-shot

  • Zero-shot — state the task with no examples. Fits simple, familiar tasks.
  • Few-shot — include one to three examples (input + output) so the model matches the format and style.

Unit tests can serve as examples: write the tests first, then ask Copilot to write a function that passes them.

NotesBest practices

  • Break complex tasks into simple, small steps.
  • Avoid ambiguity — ask "what does the createUser function do" instead of "what does this do".
  • Specify libraries — set imports at the top or name the library you want.
  • Provide relevant context — @ attach files, # attach issues/PRs, highlight code.
  • Keep history relevant — start a new session for a new task; remove irrelevant turns.
  • Experiment and iterate — if not happy, adjust the prompt and retry.
  • Review output — assess, test, and confirm like reviewing a colleague.

NotesHow context is determined

Context comes from multiple sources depending on the surface: open files in the IDE, highlighted code, items attached with @/#, and instruction files such as .github/copilot-instructions.md or AGENTS.md. The more precise the context, the more relevant the answer.

PracticeTry it

  • 1. General → specificWrite a prompt for a date-handling function: state the goal, then list format and edge cases.
  • 2. Few-shotGive two input/output examples before asking Copilot to produce a third.
  • 3. Tests as examplesWrite unit tests first, then ask Copilot to write a function that passes them.
  • 4. Attach contextUse @ to attach the right file, then ask to modify a function in it.
