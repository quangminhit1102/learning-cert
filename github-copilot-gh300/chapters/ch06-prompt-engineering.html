Chương 06 Prompt Engineering & Context Crafting

Prompt engineering và tạo ngữ cảnh

Chất lượng câu trả lời phụ thuộc rất lớn vào cách bạn viết prompt và cung cấp ngữ cảnh. Đây là kỹ năng trực tiếp được đo trong đề thi.

Bức tranh lớn

Prompt tốt = rõ mục tiêu + đủ ví dụ + đúng ngữ cảnh + lặp lại. Copilot dùng cả prompt lẫn ngữ cảnh xung quanh để trả lời.

Tự kiểm tra5 điều bắt buộc nhớ

  1. Thứ tự viết prompt tốt nhất?

    Bắt đầu tổng quát, rồi cụ thể dần; yêu cầu quan trọng nhất đặt đầu/cuối prompt.

  2. Vì sao nên cho ví dụ?

    Ví dụ input/output giúp Copilot hiểu đúng định dạng và hành vi mong muốn.

  3. Zero-shot và few-shot khác nhau thế nào?

    Zero-shot không kèm ví dụ; few-shot kèm vài ví dụ để định hướng.

  4. Cách cung cấp ngữ cảnh?

    Mở file liên quan, highlight code, dùng @ (file/symbol) và # (issue/PR), instructions files.

  5. Nên làm gì khi kết quả chưa ưng?

    Thử lại, chỉnh prompt, giữ lịch sử liên quan — lặp đến khi đạt.

Ghi chúCấu trúc prompt

Một prompt gồm yêu cầu + ngữ cảnh. Quy tắc: nêu mục tiêu tổng quát trước, rồi liệt kê yêu cầu cụ thể, đặt điều quan trọng nhất ở đầu và cuối vì Copilot ưu tiên chúng.

Nói thẳng quy tắc thay vì meta-instruction: viết "Trả về JSON" thay vì "hãy nhớ luôn trả về JSON".

Ghi chúZero-shot và few-shot

  • Zero-shot — chỉ nêu nhiệm vụ, không kèm ví dụ. Phù hợp task đơn giản/quen thuộc.
  • Few-shot — kèm 1-3 ví dụ (input + output) để model bắt chước định dạng và phong cách.

Unit test cũng có thể dùng làm ví dụ: viết test trước, rồi yêu cầu Copilot sinh hàm thỏa các test đó.

Ghi chúCác thực hành tốt

  • Chia nhỏ task phức tạp thành nhiều bước đơn giản.
  • Tránh mơ hồ — hỏi rõ "hàm createUser làm gì" thay vì "cái này làm gì".
  • Nêu rõ thư viện — đặt import ở đầu file hoặc nói rõ thư viện muốn dùng.
  • Cung cấp ngữ cảnh liên quan — @ gắn file, # gắn issue/PR, highlight đoạn code.
  • Giữ lịch sử liên quan — bắt phiên mới cho task mới; xóa lượt không cần.
  • Lặp và thử lại — không ưng thì sửa prompt và chạy lại.
  • Xem lại kết quả — đánh giá, test, xác nhận như review đồng nghiệp.

Ghi chúNgữ cảnh được xác định thế nào

Ngữ cảnh đến từ nhiều nguồn tùy bề mặt: file đang mở trong IDE, đoạn code được highlight, các item gắn bằng @/#, và các file hướng dẫn như .github/copilot-instructions.md hay AGENTS.md. Ngữ cảnh càng chính xác, câu trả lời càng sát ý.

Thực hànhÁp lên máy

  • 1. Tổng quát → cụ thểViết prompt sinh hàm xử lý ngày: nêu mục tiêu, rồi liệt kê định dạng và edge case.
  • 2. Few-shotĐưa 2 ví dụ input/output trước khi yêu cầu Copilot sinh trường hợp thứ ba.
  • 3. Test làm ví dụViết unit test trước, rồi nhờ Copilot viết hàm vượt test đó.
  • 4. Đính ngữ cảnhDùng @ để gắn đúng file, rồi yêu cầu sửa một hàm trong đó.

Một trangCheat sheet

Cấu trúc

  • Tổng quát trước, cụ thể sau
  • Quan trọng nhất đầu/cuối
  • Nói thẳng quy tắc

Kỹ thuật

  • Cho ví dụ (few-shot)
  • Chia nhỏ task
  • Tránh mơ hồ
  • Lặp lại nếu chưa ưng

Ngữ cảnh

  • Mở file liên quan
  • @ file · # issue/PR
  • instructions / AGENTS.md

Ngoài sáchMẹo thi bổ sung

  • Câu hỏi hay cho một tình huống và hỏi "cải thiện prompt bằng cách nào" — chọn đáp án thêm ví dụ/ngữ cảnh/chia nhỏ.
  • Ghi nhớ zero-shot = không ví dụ, few-shot = có ví dụ.
