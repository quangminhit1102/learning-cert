Chapter 05 Data & Architecture

Data and architecture

Understand how Copilot processes data — from your keystrokes to the displayed suggestion — and the limits of language models.

The big picture

Copilot = your context (prompt + code + open files) → build a prompt → send to the model → process the result → show a suggestion. Quality depends on both context and LLM limits.

Recall check5 things you must remember

  1. What does Copilot use to build a prompt?

    Your prompt plus context (current code, open files, chat history).

  2. What is a code suggestion's lifecycle?

    Type → gather context → build prompt → send to model → response → post-processing → display.

  3. What are proxy filtering and post-processing for?

    Applying content exclusions before sending; filtering results (like public-code matches) before showing.

  4. How does data handling differ between individual and Business/Enterprise plans?

    Business/Enterprise don't use data for training; individual plans may use telemetry unless opted out.

  5. What are the main LLM limits?

    Limited context window, nondeterministic, and can be wrong or insecure.

NotesData flow and usage

When you use Copilot, what is sent includes your prompt and surrounding context (code, open files). Whether data is retained or used for product improvement depends on the plan:

  • Copilot Business / Enterprise — prompts and suggestions are not used to train models.
  • Copilot Free / Pro (Individual) — GitHub may use telemetry and code snippets for product improvement, depending on your settings.

NotesInput processing and prompt building

Input processing: Copilot combines your prompt with selected context (current code, open files, conversation history) into a full prompt sent to the model. Proxy filtering applies rules (such as content exclusions) before data leaves your machine; post-processing filters or adjusts the result (e.g. dropping public-code matches) before display.

NotesCode suggestion lifecycle

  1. You type code or make a request.
  2. Copilot gathers context.
  3. The prompt is built.
  4. The model generates a response.
  5. Post-processing (filtering, public-code blocking).
  6. The suggestion is shown; you accept or dismiss.

NotesLLM and Copilot limitations

  • Limited context window — the model can only "see" a certain amount; excess context may be dropped.
  • Nondeterministic — the same prompt can return different results.
  • Can be wrong — may produce incorrect logic or non-existent APIs.
  • No security guarantee — generated code may contain vulnerabilities.

PracticeTry it

  • 1. Observe contextOpen 3 related files and ask Copilot about a function; close 2, ask again, compare.
  • 2. Test nondeterminismSend the same prompt twice and compare the results.
  • 3. Test filteringPut a file in a content exclusion and confirm Copilot no longer uses it.
  • 4. Memorize the lifecycleRedraw the 6-step suggestion lifecycle from memory.
