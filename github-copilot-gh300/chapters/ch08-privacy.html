Chapter 08 Privacy, Exclusions & Safeguards

Privacy and safeguards

Control what Copilot can read, filter public-code matches, and know what to do when suggestions or exclusions don't behave as expected.

The big picture

You decide what Copilot sees (content exclusions) and what it returns (public-code filter). These two layers protect your data and copyright.

Recall check5 things you must remember

  1. At which levels do content exclusions exist?

    Repository, organization, and enterprise levels.

  2. How is content exclusion configured?

    In repo, organization, or enterprise settings (or via the REST API) — not in a single file.

  3. What is the public-code filter for?

    Blocking suggestions that match public code (suggestions matching public code).

  4. Who owns the code you write with Copilot?

    You own the code you write; just watch for public-code matches and licensing.

  5. What if exclusions/suggestions misbehave?

    Check the configuration, exclusion scope, and troubleshoot per GitHub's guidance.

NotesContent exclusions

Content exclusions stop Copilot from accessing sensitive content. Repository admins, organization owners, and enterprise owners can configure them at three levels:

  • Repository-level — set in the repo's Settings (affects users working in that repo).
  • Organization-level — rules for users assigned a Copilot seat through that org.
  • Enterprise-level — rules that apply to all Copilot users in the enterprise.

Org and enterprise owners can also manage exclusions programmatically via the REST API.

Content exclusion is a guardrail, not a filesystem security boundary: it is not guaranteed to be respected by third-party MCP servers or clients, and it may miss indirect file access (such as type information provided by the IDE).

NotesOwnership and output limits

You own the code you write (including with Copilot's help). However, suggestions may match public code — then you must consider the license before using it. Copilot does not guarantee the code is free of copyright issues.

NotesPublic-code matching filter

The suggestions matching public code feature blocks suggestions that match public code. When enabled, Copilot won't show suggestions matching public code (with a source reference). Configure it in Copilot Settings.

NotesTroubleshooting

  • Suggestions still come from excluded files → check the paths/patterns in the exclusion settings.
  • No suggestions → confirm inline suggestions are enabled and you're signed in with a seated account.
  • Org-level exclusion not effective → check the admin policy and the audit log for changes.

PracticeTry it

  • 1. Configure a repo exclusionAdd a sensitive file in Repo Settings → Copilot → Content exclusion, confirm Copilot no longer uses it.
  • 2. Enable the public-code filterIn Copilot Settings, enable "Suggestions matching public code".
  • 3. Test exclusionsExclude a folder, then ask Copilot about its contents.
  • 4. Read ownershipCheck the license of Copilot-suggested code before using it in a project.
